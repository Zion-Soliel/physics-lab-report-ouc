# 大学物理实验报告 Skills

为中国海洋大学《大学物理实验（一）》与《大学物理实验（二）》制作的 AI Agent 工作流：辅助整理预习原理、处理实验数据、估算不确定度、绘图和撰写实验报告。

本仓库提供两个可分别安装的 skill：[预习报告](skills/physics-lab-prelab/SKILL.md)与[实验报告](skills/physics-lab-report/SKILL.md)。下载时请完整保留各自的 `references/`。

## 为什么做这个项目

这个项目起初是为我自己完成中国海洋大学大学物理实验一、二的实验报告而制作的。

实验后的重复工作很多：整理数据、检查单位、计算物理量与不确定度、调整图形、把计算过程写成适合实验报告纸的形式。我希望把这些流程沉淀为可复用的 skill，节省整理和作图时间，把更多精力留给理解实验、检查结果和分析误差。

项目在实际使用中逐渐形成了两个相互独立的 skill：预习报告和实验报告。它们记录的不只是一个提示词，还包括资料读取方式、课程处理规则、报告组织习惯和真实使用中发现的问题。

这是个人发起的社区项目，不是学校或课程组发布的官方工具。不同教师、学期与实验项目的要求可能不同，使用时以本次讲义和教师要求为准。

## 可以做什么

| Skill | 使用阶段 | 输入 | 主要输出 |
| --- | --- | --- | --- |
| `physics-lab-prelab` | 实验前 | 讲义、教师指定范围、补充要求 | 含实验仪器、实验原理、必要公式和配图的 Markdown 预习报告 |
| `physics-lab-report` | 实验后 | 原始数据、讲义、教师要求、仪器信息；已有预习稿可选 | 手写正文、独立图表附件、PNG 图及计算绘图脚本 |

两个 skill 可以分别安装，不需要先运行预习 skill 才能运行实验报告 skill。这里的“子 skill”表示同一项目下的两个工作流，不表示必须启动两个子 agent。

### 预习报告

- 根据实际讲义提炼原理，不只按实验名称生成通用内容。
- 识别教师图片里的必做、选做、删线和“只做幅频”等限制；教材编号不同，按项目内容对应。
- 优先从讲义整理实验仪器；没有单独仪器清单时，从实验内容归纳，按需要补充通用器材，不编造型号和精度。
- 原理按项目分条，说明机制、条件、分类与连接关系，配关键公式和符号解释。
- 读取文字 PDF；扫描 PDF 需要宿主具备页面渲染或图像阅读能力。重要公式回原页面核对。
- 在对应小节放置电路图、装置图、函数曲线。讲义原图注明来源；重绘图和理论图明确标识。
- 默认原理叙述正文在 **400 字以内**。这不是整个文件的长度限制：仪器、标题、公式、简短符号解释、图题及来源说明另计；不通过这些部分塞入长篇分析规避限制。

### 实验报告

- 设计有表名、物理量及单位的数据表，区分原始读数和处理结果。
- 给出规范的计算公式、关键代入、单位及结果；重复逐点换算放在结果表中。
- 处理直接量、间接量和必要的拟合参数不确定度，说明分量来源、条件和简化范围。
- 用 Python 生成 PNG 图，包含图名、坐标轴、物理量、单位、图例，区分测量点、拟合线和理论线。
- 检查跨项目依赖，例如某实验要求引用另一项的标定、表格或单独测量曲线。
- 默认把适合手写的正式正文与图表附件分开，正文保留准确的图表引用。
- 默认“实验结果和讨论”约 **1000 字**，围绕本次结果展开误差机制、思考或延伸和改进方案；不因手写而压缩科学分析。
- 根据反馈局部修订，保留已经认可、无需修改的部分。

### 能力边界

这是给 agent 使用的指令与参考资料，不是独立运行的报告软件，也不是包含所有实验算法的固定计算程序。实际计算脚本由 agent 针对本次数据生成并执行。

它不能替代实际测量、实验理解或最终核对；不能补造缺失实测值，不能把理论曲线当作测量结果。格式合格也不代表教师一定接受。请遵守课程关于 AI 辅助、独立完成和资料使用的规定。

当前实际使用案例是磁学综合实验和 RLC 电路综合实验；尚未验证课程全部实验项目。其他实验可按提供的讲义尝试，但不应据此宣称已全面适配。

## 先准备哪些资料

### 做预习报告

| 资料 | 必要程度 | 建议提供方式 |
| --- | --- | --- |
| 本次实验讲义或教材相关章节 | 必需 | 完整相关 PDF，保留原理、公式、图和实验内容 |
| 教师指定范围 | 必需提供或明确说明做全部 | 要求截图或文字，说明必做/选做、只做哪部分 |
| 字数、结构、提交格式等要求 | 有则提供 | 直接在提示词中写明；否则使用默认格式 |
| 希望模仿的预习稿 | 可选 | 你有权使用的 Markdown、文档或图片 |

### 做实验报告

| 资料 | 必要程度 | 为什么需要 |
| --- | --- | --- |
| 原始实验数据 | 必需 | 优先 XLSX/CSV；也可用清晰记录照片，但需要核对识别结果 |
| 本次实验讲义及教师范围 | 必需 | 确定模型、计算方式、必需表格和曲线 |
| 列名、单位、正负号与测量条件 | 必需信息 | 避免将 mA 当 A、将带符号读数变成绝对值等 |
| 仪器量程、分辨率、准确度或允差 | 不确定度计算所需，尽量提供 | 可拍铭牌或说明书相关页；不知道时明确写“不知道” |
| 课程不确定度、有效数字、作图要求 | 有则提供 | 本项目的既有课程规则不自动适用于所有教师和学校 |
| 已完成的预习报告 | 建议 | 保持符号与实验范围一致，公式仍应回讲义核对 |
| 已有报告及修改意见 | 修订时提供 | 指定需要改哪一部分、哪些部分已认可 |

如果数据已做修正，请主动说明：例如“坐标已扣除 15 mm”“电压已扣零点”“这一列已取平均值”。也请说明某个常数来自仪器标定、教材参数还是前一实验计算，防止重复修正或循环验证。

可以按以下结构建立本地实验工作区，文件名可以自行修改：

```text
我的实验/
├── input/
│   ├── 实验讲义.pdf
│   ├── 教师要求.png
│   ├── 原始数据.xlsx          # 预习阶段不需要
│   ├── 仪器参数.png           # 如有
│   └── 课程数据处理要求.pdf   # 如有
├── notes.md                  # 已知条件、修正情况、补充要求
└── output/                   # 生成结果
```

**本地 agent**：可以提供它有权读取的文件路径。**云端或远程 agent**：需要上传实际文件，或放进该环境的工作区；发送你电脑上的 `D:\...` 路径并不等于上传。手写照片要保留完整表头、单位、小数点和正负号。

## 输出文件是什么样的

预习报告的典型结构：

```text
output/
├── 实验名称-预习报告.md
└── 实验名称-预习配图/
    ├── 电路图.png
    └── 特性曲线.png
```

实验报告的典型结构：

```text
output/实验名称/
├── 手写正文.md
├── 图表附件.md
├── 计算与绘图.py
├── figures/
│   └── 图1.png
└── 核查说明.md        # 需要说明来源、假设或复现方法时
```

这些是组织示意，不强制每个任务使用完全一致的文件名。详解版、Word 或 PDF 按要求另做。Markdown 和 PNG 是默认交付，Markdown 文件本身不等于已经排版好的打印 PDF。

转移报告时要连同配图文件一起复制；如果 Markdown 中用了本地绝对路径，换电脑或在 GitHub 展示前，需要转换为对应的相对路径。

## 运行环境与数据处理约定

下载 skill 不需要配置本项目专用 API Key。实际调用的模型、订阅或 API 费用由你使用的 agent 服务决定。

完整任务通常需要宿主能够读写文件、阅读 PDF/图片、运行 Python 并保存结果。常用工具包括：

| 工作 | 可用工具示例 | 说明 |
| --- | --- | --- |
| PDF 文字提取 | pypdf、pdfplumber | 扫描版可能提取不到文字 |
| PDF 页面查看 | PDFium、Poppler、宿主 PDF 工具 | 用于核对原公式和提取原图 |
| 表格读取 | openpyxl、pandas | XLSX/CSV 按实际格式选择 |
| 数值处理与绘图 | NumPy、Matplotlib；必要时 SciPy | 科学曲线使用计算工具生成 |
| 中文显示 | 环境中可用的中文字体 | 不依赖某台 Windows 的固定字体路径 |

这些是可选实现工具，不是安装 skill 时必须一次装全的依赖。优先使用宿主已有工具；确需新增依赖时使用该环境允许的安装方式，避免写死作者机器的 Python 路径。

实验报告 skill 中保留了最初课程的处理习惯，例如特定条件下取 `t=1`、不确定度默认一位有效数字。它们是**有适用范围的课程约定**，不是所有实验的普遍规则。教师另有要求时应覆盖；采用估计、独立性假设或讲义外补充方法时应说明。

## 常见问题

**可以只上传实验名称吗？**

不建议。课程版本、仪器和教师指定项目可能不同。至少提供相关讲义与范围，才能按实际材料写。

**没有单独的仪器页怎么办？**

skill 会从实验内容和装置图归纳必要器材；讲义未列出的通用连接器材可以合理补充，型号与精度不能凭空填写。

**扫描讲义能用吗？**

可以尝试，前提是 agent 能查看页面图像。若不能读取，需换有图像能力的环境或上传清晰页面图片，不应让它根据空白提取结果猜公式。

**有了预习报告，还需要再上传讲义吗？**

做实验后报告时仍建议提供。预习报告是摘要，可能没有仪器规格、全部表格或标定步骤。

**为什么缺数据时没有把所有图补齐？**

例如只有双线圈合成场，不能唯一还原两组单线圈实测数据。可以给明确标识的理论对照，但不能假装已经完成独立实验验证。

**为什么调用后只回复一段话，没有生成文件？**

检查宿主是否可以写文件、是否真的读取了 SKILL.md，以及任务是否指定输出位置。只会聊天的环境不能保证交付实际 PNG 或脚本运行结果。

**为什么 `/skill-name` 或 `$skill-name` 没有效果？**

不同宿主使用不同语法。检查安装目录，避免多套一层仓库目录；确认 `SKILL.md` 与 `references/` 同在一个 skill 文件夹内。必要时显式提供 SKILL.md 路径。

**是不是所有 agent 都能生成同样结果？**

不是。模型能力、文件工具、执行环境和资料完整程度都会影响结果。重要公式、关键数值和最终结论仍需人工核对。

## 欢迎一起改进

如果你也在做大学物理实验，欢迎把实际使用中遇到的问题带回来。贡献不一定是写代码：一句更清楚的安装说明、一个漏掉的物理条件、一份有授权的匿名案例，都能帮助后来的同学少走弯路。

特别欢迎：

- 中国海洋大学不同学期、教师要求的差异整理，明确适用范围。
- 新实验的可复现案例：提供可以公开的材料、原始数据和核对过程。
- 公式、量纲、不确定度、拟合方法与图表标注的纠错。
- Claude Code、DeepSeek Harness、WorkBuddy 的真实安装和运行记录。
- Linux/macOS、中文字体、扫描 PDF、宽表打印等兼容性改进。
- 更好的报告表达、示例和对新手友好的提示词。

提交 Issue 时，请说明实验项目、使用的 agent 和版本、输入格式、期望行为、实际问题与最小复现资料。需要展示数据时先去掉姓名、学号、联系方式和不相关记录；不要直接上传整本受限教材或未获授权的讲义。

提交 PR 时尽量聚焦一个问题，说明改了什么、为什么改、如何核对。涉及计算的改动应附手算或独立复算依据，涉及图形的改动应展示结果。不要只用“看起来更好”替代科学正确性验证。
